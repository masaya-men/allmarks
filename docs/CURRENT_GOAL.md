## ★★公開前(claimレコードseed=誰かが同期を使える状態にする前)に残っているのはI-5のみ

I-5は2つに分かれていて、**コードで解ける部分は既に閉じた**(下記)。残るのは製品判断のみ:

- **✅ 解決済み**: まとめ先の公開鍵が壊れている/改ざんされている場合に静かに壊れる、という懸念 → 実際には`mergeIntoOtherVault`は`importPublicKey`を最初の行で呼んでおり、壊れた鍵なら即座に例外を投げ、何も変更せず安全に中断することを実際にテストで確認済み(`lib/private/vault-conflict.test.ts`の「malformed target public key」テスト)。
- **⏳ 製品判断が必要(コード修正では閉じない)**:
  1. **パスワードを本当に忘れた場合、復旧手段が無い** — これはPrivate機能自体が最初から持っている前提(vault食い違いが無くても今日から既に真)であり、今回の束6③が新たに生んだリスクではない。まとめ機能によって「2台分のデータが1つのパスワードに依存する」形になる分、影響範囲は広がる。
  2. **Googleアカウント乗っ取りレベルの攻撃者による`pickDeterministic`の意図的な誘導** — Driveへの書き込み権限が前提(既存のBYOS設計が元々受け入れているリスクの範囲内)。
  - **次回、ユーザーと相談して方針を決める**: (a) 現状(復旧手段なし)を受け入れて公開する、(b) 復旧コードのような新機能を将来的に検討する、のどちらかを選ぶ。コードで今すぐ閉じられる話ではないため、次回セッション開始時にこの2択を提示する。
