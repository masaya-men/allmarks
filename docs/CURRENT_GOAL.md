- **鍵配布の仕組みも確定・技術的にはs218で実証済み**: FANBOXは会員を自動確認する公式APIを持たないため、「合言葉リンク方式」(`allmarks.app/claim?c=<秘密文字列>`をFANBOXの会員限定投稿に貼る→クリックでプール済みのユニーク鍵を1個自動払い出し)を自作する。この仕組み自体はK3として実装済みで、s218でユーザー自身の招待コードを実際に発行し2端末で同期接続まで実機確認済み。**ゼロから作る必要はなく、同じ仕組みを流用するだけでよい**。
- **価格も確定済み**: ¥500(基本)/¥1,500(大応援・アプリ内解錠は¥500と同じ、差分はFANBOX側の名前クレジット等の特典のみ)。
- **役割分担も確定済み**: 口座開設(本人確認・銀行口座連携)は必ずユーザー本人の作業(Claudeは代行不可)。Claudeの役割は、支援ページに載せる文面の下書き(`docs/private/`に置く)と、アプリ内の「応援」導線の配線。

## 恒久ルール(継承)

- 視覚変更は`ui-design.md`「承認後」。`rtk`前置・`--no-verify`禁止・vitest/playwrightは素のnpx(`rtk npx`は既知の不具合)・Framer Motion禁止。
- 音(dotted-notebook)/紙(paper-atelier)/Flat のテキストカードは今回で統一済み(共通の`renderMetaStrip()`経由)。今後この部分に手を入れれば全テーマへ自動反映される。
- 機微(支援・値付け・戦略)はtrackedに書かない＝`docs/private/`。
- merge/push/deployは必ずユーザー確認後。ただしdeployは「本番で見たい」等の明示的な合図があれば即実行可。docsだけのpushはしない(次の実務pushに同梱)。
- 選択ボックス(AskUserQuestion)はデザイン判断・意思決定・調査/デバッグ中の質問には使わない。普通の会話で聞く。
- 文言(UIコピー)を新規/変更するときは、実装前に実際の英語・日本語の文面そのものを見せて確認を得ること。**ユーザーが指定した具体的な値(文字列など)は、実装前にそのまま使うこと**。
- IDB/vault・同期のmerge処理など不可逆な本番データに関わる変更は、実行前に必ずユーザーに事実確認する。
- 大規模調査・実装はサブエージェントに委譲(司令塔は診断・設計・指示書・検収)。同一ファイルへの並行実行は避ける。
- **収益化のような大きな話題を再開するときは、`docs/private/`の既存資料を実際に読み直して既決事項を洗い出してから会話を始める**(ユーザーに再度決めさせる/繰り返し尋ねるのを避ける — s219で指摘を受けた教訓)。
